# Screen: Lend a book

Slice `Lend book` · node `5b76ad08-9d54-459f-b0ef-36e1cb0501e8` · written by the loop on 2026-11-16.

Mockup: designed on the board — `get_node` with the id above (one page: a "Book" select
showing "Title — Author" with the help text "Only books that are available.", a "Member"
text input, a "Due on" date input, a "Lend book" button and a "Cancel" button).

## How it's entered

The book picker is filled from the `Catalogue` slice (the screen's `books`, `authors` and
`available` fields map to `Catalogue.title` / `Catalogue.author` / `Catalogue.available`):

```elixir
Library.Slices.Catalogue.Context.catalogue() :: [
  %{book_id: String.t(), title: String.t(), author: String.t(), available: boolean()}
]
```

The form is built from the command (`loan_id` and `lent_at` are generated by the Context,
pass them as the derived second argument only if the form needs them to validate):

```elixir
to_form(Library.Slices.LendBook.LendBook.changeset(params))
```

## What it returns

From the catalogue, one option per book:

| field | type | | what it is |
|---|---|---|---|
| `books` | `String` (list) | | mapped to `Catalogue.title` |
| `authors` | `String` (list) | | mapped to `Catalogue.author` |
| `available` | `Boolean` (list) | | mapped to `Catalogue.available`; the mockup lists only available books |

The form's fields:

| field | type | | what it is |
|---|---|---|---|
| `bookId` | `UUID` | required | the selected book, mapped to `LendBook.bookId` |
| `memberId` | `String` | required | mapped to `LendBook.memberId` (mockup example `M-1042`) |
| `dueOn` | `Date` | required | mapped to `LendBook.dueOn` |

## What it sends back

```elixir
Library.Slices.LendBook.Context.lend_book(%{
  "book_id" => book_id,
  "member_id" => member_id,
  "due_on" => "2026-12-07"
})
# {:ok, loan_id}                    # generated loan id
# {:error, %Ecto.Changeset{}}       # a field missing/blank (validation: :required) or due_on not a date (validation: :cast)
# {:error, :book_not_found}         # board: "A book that was never added can't be lent"
# {:error, :book_already_lent}      # board: "A book already lent can't be lent again"
# {:error, :member_holds_two_books} # board: "A member holding 2 books can't borrow a third"
# {:error, :store_unavailable}      # the event store isn't up
```

Domain error atoms to translate: **`:book_not_found`**, **`:book_already_lent`**,
**`:member_holds_two_books`**. Plus `:store_unavailable` (infrastructure).

## States to render

- Empty catalogue, or no available book: nothing to lend.
- Form with a book selected, member and due date.
- Field errors once touched or submitted (`used_input?/1`).
- Submitted: `{:ok, loan_id}` — the catalogue now shows the book as not available; where to go next isn't on the board.
- A domain error or `:store_unavailable`: the loan was not recorded, the inputs must survive.

## What the board says about this screen

The screen node has no `description`.

## What the domain does NOT give you

- No member directory: `memberId` is free text, the domain checks nothing about it except
  how many books that id holds.
- No rule on `dueOn` (not in the past, not after a maximum period): any date is accepted.
- No default due date or loan period: the screen's input decides it.
- `lentAt` is set by the Context at the moment of the call; the screen doesn't send it.
- "Cancel" has no domain counterpart; it's navigation only.
