# Screen: Add a book

Slice `Add book` · node `dcdf69a5-0129-433f-9d22-adeb4810a108` · written by the loop on 2026-11-16.

Mockup: designed on the board — `get_node` with the id above (one page: a form with
Title, Author, an "Add book" button and a "Cancel" button).

## How it's entered

The screen starts empty: it reads nothing. The form is built from the command:

```elixir
to_form(Library.Slices.AddBook.AddBook.changeset(params))
```

## What it returns

Nothing is read. The form's fields:

| field | type | | what it is |
|---|---|---|---|
| `title` | `String` | required | mapped to `AddBook.title` |
| `author` | `String` | required | mapped to `AddBook.author` |

## What it sends back

```elixir
Library.Slices.AddBook.Context.add_book(%{"title" => title, "author" => author})
# {:ok, book_id}
# {:error, %Ecto.Changeset{}}   # title or author missing/blank (validation: :required)
# {:error, :store_unavailable}  # the event store isn't up
```

`book_id` is generated by the domain; the screen never sends it.

Domain error atoms: **none** — the board has no rejection rule for this slice.
Only `:store_unavailable` (infrastructure) needs words.

## States to render

- Empty form (initial).
- Field errors once a field is touched or the form submitted (`used_input?/1`).
- Submitted: `{:ok, book_id}` — the book is in; where to go next isn't on the board.
- `:store_unavailable`: the book was not added, the inputs must survive.

## What the board says about this screen

The screen node has no `description`.

## What the domain does NOT give you

- No ISBN, year, copies, cover or any other book field: only `title` and `author`.
- No duplicate check by title/author — two books with the same title are two books,
  deliberately (no such rule on the board).
- No list of existing books here: that is the `Catalogue` slice.
- "Cancel" has no domain counterpart; it's navigation only.
